# Data Model & State Machines — 004 Group Chat

**Status:** DESIGN ONLY, no Java classes or schema implemented · **Date:** 2026-11-21
**References:** [Spec](spec.md) · [Plan](plan.md) · [Group wire contract](contracts/group-v1.md) · [M2 data model](../003-p2p-messaging/data-model.md).

## 1. Identity and key rules

- `deviceId` = stable UUID bound to verified ECDSA P-256 SPKI hash from M2. Mutable displayName/IPv4/port **not identifiers**.
- `groupId` = random nonzero UUID (unique group identity); not an access token or authorization. Multiple groups may share displayName or roster.
- `ownerEpoch` = monotonically increasing unsigned-positive long/64-bit integer per Group, incremented **only** after dual-signed voluntary owner handoff. Strict overflow reject and fail closed.
- `membershipRevision` = monotonically increasing unsigned-positive long in one ownerEpoch, incremented on **committed roster/name/disband changes**; reset to 1 only on new ownerEpoch if agreed contract enforces clear epoch binding. **Recommended:** carry revision forward across handoff (no reset), makes stale comparison straightforward.
- `groupRunId` = random UUID generated by owner at each activation/restart/handoff, **RAM only**. A signed owner activation/snapshot binds it to current epoch/revision. Old run replay is rejected.
- `ownerSequence` = 1-based long per Group run, assigned by one owner serial executor when accepting Group text; provides within-run order, not cross-restart causality.
- `identity proofs` = ECDSA P-256 `SHA256withECDSA` signatures over canonical bytes for events and Group text/receipts. A signed owner claim is not a direct pin for an unknown member.

## 2. Durable vs ephemeral entities

| Entity / fields | Persist? | Invariants / validation |
| --- | --- | --- |
| **GroupMetadata**: groupId, displayName, createdAtUTC, ownerId, ownerPinnedSpkiHash, ownerEpoch, membershipRevision, rosterDigest, state, lastOwnerEventDigest, transferProof, tombstone | **YES**, encrypted DPAPI CurrentUser | ≤8 groups per Windows user; no credentials/secrets/content; fail closed on corrupt/version/ACL |
| **GroupMemberRef**: deviceId, pinnedSpkiHash, role (OWNER/MEMBER), joinRevision, leaveRevision, activeFlag | **YES** in GroupMetadata | ≤5 unique members incl 1 owner; no displayName/IP as identity; role derived from verified owner key and authoritative event |
| **OwnerHandoffProof**: transferId, groupId, oldOwnerId, newOwnerId, prevEpoch, nextEpoch, rosterDigest, revision, oldOwnerSignature, newOwnerAcceptanceSignature, commitDigest | **YES** while relevant for continuity | A must durably retire first; B only active after persisting proof; no unilateral owner increase |
| **GroupStoreTombstone**: groupId, deletionReason enum, ownerEpoch, revision, eventProof if available | **YES** until explicit local retention policy expiry | Local delete cannot automatically grant fresh invite or override owner revocation; no message IDs or chat text |
| **InviteProposal**: proposalId, groupId, proposerId, inviteeId, deadline, state | **NO** | Only current member can propose; owner approval required; replay/TTL bound |
| **GroupInvitation**: invitationId, ownerId, invitedDeviceId, request nonce, expireAt, decision, current epoch/revision | **NO**, incl nonce/token | Strict owner signature and invitee opt-in before join commit |
| **GroupSession**: groupId, current owner active TLS session, peer verifiedId, groupRunId, capability agreement, roster sync status, last sequence | **NO** | All ACTIVE sessions verified READY+Group caps; on restart PAUSED |
| **GroupMessage**: originalMessageId, groupId, originId, epoch/revision/runId, sentAtUTC, text, contentHash, signature, ownerSequence, recipientSnapshot | **NO** | Immutable signed content; recipient snapshot from owner committed roster |
| **RecipientDelivery**: originalMessageId, viewer/recipientId, evidence status, correlated envelopeId/receiptId, epoch/revision/runId, attempted session, time | **NO** | Per-recipient monotonic states, never infer READ from ACK |
| **GroupDraft**: groupId, local editorId, text, updatedAtUTC | **NO** | RAM only; reconnect/restart never sends automatically |
| **DedupWindow**: (groupId, runId, originId, originalMessageId) → contentHash/acceptedAt | **NO** | 1,024 IDs / 30min; reuse ID with changed hash rejected |
| **GroupViewEvent**: groupId, originalMessageId, visibleAtUTC, Live foreground+viewport proof | **NO** | Only real Swing Live; ≥250ms visible; one read event/session, not human cognitive read |

**Important privacy difference:** Metadata includes who belongs to a Group, which **is sensitive**, even without message text. Encrypt and restrict access. Do not persist invitation secret/one-time nonce, message IDs, sender text, message attempt statuses, read events or chat timestamps that reveal conversation content. If audit trail is requested later, it is a new privacy/scoping decision.

## 3. Group state transitions

| Current state | Trigger + guard | Next state | Durable mutation? |
| --- | --- | --- | --- |
| ABSENT | Local verified owner creates valid groupName; ≤8 groups | CREATED | New metadata: owner-only roster, epoch=1, revision=1 |
| CREATED | Owner invites members on verified channel | INVITING | No roster change until accepted/commit |
| CREATED/INVITING | Owner accepted invitee opt-in, capacity ≤5, durable roster commit | ACTIVE if owner connected; else PAUSED | Revision +1 and signed roster |
| ACTIVE | Owner verification/transport lost | PAUSED | No false persistence of online presence |
| PAUSED | User manually connects to current owner, passes M2 READY+caps and signed roster/run sync | ACTIVE | Save latest signed metadata if newer |
| ACTIVE | Owner begins accepted successor transfer, pauses accepts | TRANSFERRING | PREPARED/RETIRE stage protected |
| TRANSFERRING | A retire durable, B commit proof validated and persisted | ACTIVE under owner B, epoch+1 | Old owner retired proof, new owner active proof |
| TRANSFERRING | Timeout before irreversible retire | ACTIVE under owner A after signed safe abort | Clear PREPARE safely |
| TRANSFERRING | Ambiguous after irreversible retire/crash | PAUSED | No owner e active until proof/recovery |
| ACTIVE/PAUSED | Owner signs DISBAND and commits | DISBANDED | Durable tombstone & revision |
| DISBANDED | Any GROUP_TEXT or stale event | DISBANDED | Reject; no auto rejoin |

**Owner-only local Group (1 member)** may remain CREATED/ACTIVE without remote sockets but cannot claim test success until ≥3-client scenario. Handoff only to **existing online verified member** who independently consents.

## 4. Membership and invitation authority

| Action | Actor required | Authorized result |
| --- | --- | --- |
| Create Group | Local verified device | New group with itself as owner (no network member admission) |
| Propose invitation | Current ACTIVE member (incl owner) | Pending proposal at owner; **NO** membership rights |
| Approve proposal/send invite | Current owner (epoch/revision correct), explicit owner UI | Signed offer to verified target, **NO** membership yet |
| Accept invitation | Exact verified invitee, unexpired signed offer | Signed consent; **NO** membership until owner durable commit |
| Commit JOIN | Current owner and valid accepted offer; capacity ≤5 | Revision +1, signed roster snapshot and new rights |
| Leave Group | Current non-owner member → owner | Owner commits revision REMOVE/LEAVE; actor cannot remove others |
| Remove member | Current owner after UI confirm | Revision +1; stopped from newly initiated fan-out |
| Rename / disband | Current owner | Signed durable revision; no effect on unrelated P2P |
| Start handoff | Current owner active, eligible successor | Quiesce; PREPARE/ACCEPT/COMMIT/ACTIVATE epoch +1 |
| Publish owner Group text | Current owner and active group | Fan-out to current committed recipient roster |
| Publish member Group text | ACTIVE member to authenticated current owner | Owner verifies signature + revision and accepts/rejects |
| Send Group READ | Actual recipient device after foreground viewport event | Owner relays signed receipt; does not create viewer proof itself |

**Key checks:** every incoming event verifies sender hop TLS/SPKI, **event author signature** where required, groupId, expected ownerEpoch, membershipRevision/authority, groupRunId if message/content, freshness ID/nonce and explicit destination. Know groupId != membership. Offline or previously removed device must request current roster and **must not** be automatically reinstated by an old invitation.

## 5. Message and recipient state (per immutable recipient snapshot)

~~~text
DRAFT → SENDING → LOCAL_SENT → OWNER_ACCEPTED → RECIPIENT_ACKED → RECIPIENT_READ
            \          \                 \                    /
           FAILED     UNCERTAIN         UNCERTAIN       READ before ACK is legal
                         ^
           OFFLINE (recipient unavailable, no success evidence)
~~~

- `OWNER_ACCEPTED` = owner put original into bounded Group relay pipeline, **not** evidence all recipients accepted.
- `RECIPIENT_ACKED` = valid application-layer signed ACK from **that recipient** on correct group/original/epoch/run; owner ACK about B is not C ACK.
- `RECIPIENT_READ` = signed valid C READ from actual Live viewport event; may arrive **before** C delivery ACK and directly upgrade C to READ. Late ACK cannot downgrade.
- `FAILED` only when failure is conclusive **before** any possible send; `UNCERTAIN` on timeout/loss after attempted send. `OFFLINE` is connectivity condition, not proof a previously sent message was never read.
- Denominator of displayed x/y delivery/read counts is **original committed recipient snapshot** of each message (excludes sender). Later join/remove does not rewrite historical recipient statuses.
- Client cannot make other members read/view, and owner cannot substitute its own signature for C's receipt.

## 6. Handoff persisted state and crash recovery

| Device | Phase | Permissions |
| --- | --- | --- |
| A (old owner) | ACTIVE e | Can relay until quiesce |
| A | TRANSFERRING e, before durable retire | No new fan-out; can abort safely before irreversible commit |
| B (successor) | PREPARED e+1 | **Cannot** relay as owner, only sign readiness |
| A | RETIRED e / commit proof stored | **Never** relay as owner e again; can retransmit saved proof on user action |
| B | COMMIT RECEIVED but not saved | **Cannot** relay; must persist proof first |
| B | ACTIVE e+1 persisted | Owner may relay only after signed activation proof and roster/run sync |
| Other members | Have A+B proof e→e+1 saved | Treat B as owner; otherwise PAUSED until owner proof sync |
| Any | Conflicting owner proofs, stale backup or pin changed | PAUSED/FAIL CLOSED; requires explicit repair/re-pair |

Atomic metadata write **cannot** make distributed two-PC commits atomic; liveness may degrade under crash. The safety target is never having two **honest non-rollback** owners active under the same authoritative proof, not perfect consensus or disaster recovery. Tests must reproduce every crash boundary.

**No database schema/migration code has been introduced yet**. Versioned protected Group metadata file is a deliberately small structured snapshot, with a separate version number from network Group protocol. Before coding, freeze the wire and at-rest schema with test vectors and review.
